## 一、核心设计原则

| 原则 | 说明 |
|------|------|
| **用户意图优先** | 每个模块回答用户一个核心问题："这对我有什么用？" |
| **SEO × 转化双驱动** | 内容既为搜索引擎写，也为人写；不能顾此失彼 |
| **心理安全感** | 用户对 AI 工具有天然疑虑，需主动消除恐惧 |
| **可复用模块化** | 各 Section 独立，换工具只需替换核心变量 |

## 二、页面结构规范（Section 模板）

每个 AI 工具落地页由以下 **8 个标准 Section** 构成，顺序不可随意打乱（基于用户决策心理流程设计）：

---

### Section 1 · Hero（首屏）

**目的：** 3 秒内让用户明白"这是什么 / 解决什么问题 / 为什么我要用"

**模板结构：**
```
[主标题 H1] — 聚焦痛点或结果，不超过 10 个词（英文）/ 20 字（中日韩）
[副标题]    — 扩展说明，1-2 句，点明核心价值 + 目标用户
[主 CTA 按钮] — 行动指令，动词开头
[Social Proof 小标签] — 如："已有 50,000+ 用户使用" 或 "Product Hunt #1"
[Hero 视觉]  — 产品截图 / 动态演示 GIF / 短视频
```

**写作规则：**
- H1 必须包含核心关键词（见 SEO 规范）
- 不写功能，写**结果**（✅ "10 分钟生成专业报告" ❌ "AI 智能分析功能"）
- 避免行业黑话（✅ "自动写邮件" ❌ "NLP 驱动的语义生成引擎"）

---

### Section 2 · 痛点共鸣（Problem）

**目的：** 用户感受到"这说的就是我"，建立情感连接

**模板结构：**
```
[小标题] — "你是否也遇到过这些问题？"
[痛点列表] — 3-4 个，配 emoji 或 icon
[转折句]  — "现在有了更好的方式"
```

**写作规则：**
- 痛点要**具体**，不要宽泛（✅ "每周花 6 小时整理会议记录" ❌ "效率低下"）
- 情绪词慎用，聚焦场景描述
- 转折句作为自然过渡，不要过于生硬

---

### Section 3 · 产品介绍（Solution）

**目的：** 清晰说明产品是什么、怎么运作

**模板结构：**
```
[标题] — "介绍 [产品名]：[一句话定位]"
[3 步使用流程] — 图文结合，步骤不超过 3 步
[功能亮点] — 3-4 个核心功能，每个配标题 + 1 句说明 + icon
```

**写作规则：**
- 流程图最多 3 步（超过会引起用户焦虑）
- 每个功能亮点遵循：**功能名（名词）→ 带来的结果（动词短语）**
- 此处可加入短视频演示（转化率提升关键）

---

### Section 4 · 社会证明（Social Proof）

**目的：** 消除用户疑虑，建立信任

**模板结构：**
```
[数据背书]   — "X 万用户 / X 个国家 / 处理 X 份文档"
[用户评价]   — 3-6 条，含头像、姓名、职位（真实或匿名化）
[媒体/合作背书] — 如曾被 ProductHunt / TechCrunch 报道
[评分展示]   — G2 / Trustpilot / App Store 星级
```

**写作规则：**
- 评价必须具体（✅ "节省了我每周 4 小时的工作量" ❌ "非常好用"）
- 评价者身份要与目标用户匹配（让用户产生"跟我一样的人在用"的认同）
- 数据要真实，可保守估算但不可捏造

---

### Section 5 · 功能对比（Why Us）

**目的：** 与竞品或"旧方式"做对比，凸显差异化优势

**模板结构（二选一）：**

**方案 A：对比表格**
```
| 功能 | [产品名] | 竞品 A | 传统方式 |
|------|---------|--------|---------|
```

**方案 B：Before / After 对比**
```
[Before] 用传统方式：痛苦场景描述
[After]  用本产品：理想结果描述
```

**写作规则：**
- 不要直接点名竞品（法律风险 + 用户体验差）
- 使用"传统方式 vs 我们"的框架更安全
- 差异化要聚焦 2-3 个核心点，不要贪多

---

### Section 6 · 定价（Pricing）

**目的：** 降低转化门槛，引导用户选择

**模板结构：**
```
[标题] — "简单透明的定价"
[套餐卡片] — 推荐 3 档（Free / Pro / Team）
[推荐标签] — 在中间套餐标注 "Most Popular"
[FAQ 小模块] — 3-5 个常见定价疑问
```

**写作规则：**
- 价格锚点：先展示高价套餐，再展示目标套餐（锚定效应）
- 必须有免费试用或 Free plan（降低首次使用门槛）
- 年付 vs 月付切换，突出年付节省百分比
主 CTA 区域  →  "免费试用 ，无需信用卡"（最大化获客）

定价页套餐下方  →  "付费后 7 天内不满意可退款"（降低付费决策门槛）

年付套餐专属  →  "14 天退款保证"（提升年付转化，金额大用户更需要安全感）
---

### Section 7 · FAQ

**目的：** 解答剩余疑虑，同时贡献 SEO 长尾词

**模板结构：**
```
[标题] — "常见问题"
[手风琴组件] — 6-10 个问答
```

**必须涵盖的问题类型：**
- 安全性 / 数据隐私（AI 工具高频疑虑）
- 是否需要技术知识
- 免费版限制说明
- 退款政策
- 与竞品的区别（间接回答）

**SEO 技巧：** 问题标题用自然语言疑问句，Google 会抓取为 Featured Snippet

---

### Section 8 · 最终 CTA（Bottom CTA）

**目的：** 临门一脚，给仍在犹豫的用户最后推动力

**模板结构：**
```
[大标题]   — 聚焦结果/情感
[副文本]   — 强调低风险（免费 / 随时取消）
[主 CTA 按钮]
[信任元素] — "无需信用卡 · 5 分钟上手 · 随时取消"
```

## 三、SEO 规范

### 3.1 关键词策略（三层结构）

```
[主关键词]    — 1个，高搜索量，放入 H1、Title、URL
[次级关键词]  — 2-3个，放入 H2、正文第一段
[长尾关键词]  — 5-10个，分布在 FAQ、功能描述、Alt Text
```

**关键词研究优先顺序：**
1. 搜索工具（Ahrefs / SEMrush / Google Search Console）
2. 竞品落地页分析
3. Google 搜索下拉词 & "People Also Ask"

### 3.2 页面 TDK 规范

| 元素 | 规范 | 示例 |
|------|------|------|
| **Title** | 主关键词 + 品牌名，50-60 字符（英文） | `AI Meeting Notes Tool - Auto Summarize in Minutes \| [Brand]` |
| **Description** | 核心价值 + CTA，120-160 字符 | `Turn any meeting into structured notes instantly. No manual work. Try free.` |
| **H1** | 唯一，包含主关键词，与 Title 不完全重复 | — |
| **URL Slug** | 全小写，连字符分隔，含主关键词 | `/ai-meeting-notes-generator` |

### 3.3 技术 SEO 要求

- [ ] Core Web Vitals 达标（非必要，LCP < 2.5s，CLS < 0.1，FID < 100ms）
- [ ] 图片全部添加 `alt` 属性（包含关键词）
- [ ] Schema Markup：SoftwareApplication + FAQ Schema
- [ ] 内链：落地页链接至 Blog / Doc 页面（MVP版本暂时不用）
- [ ] 移动端适配（Google 优先移动端索引）
- [ ] HTTPS
- [ ] Canonical 标签（多语言页面必须设置）

### 3.4 多语言 SEO 规范

```html
<!-- 每个语言版本页面 <head> 中必须添加 hreflang -->
<link rel="alternate" hreflang="en" href="https://example.com/en/tool-name" />
<link rel="alternate" hreflang="ja" href="https://example.com/ja/tool-name" />
<link rel="alternate" hreflang="ko" href="https://example.com/ko/tool-name" />
<link rel="alternate" hreflang="x-default" href="https://example.com/en/tool-name" />
```

- 每个语言版本使用独立 URL（不用参数切换，如 `?lang=ja`）
- URL 结构推荐： `/ja/` `/ko/` 子目录形式，默认英文使用根目录形式
- **关键词须重新研究**，不能直接翻译英文词（各语言搜索习惯不同）

## 四、营销心理学策略层

### 4.1 说服原则对应模块

| 心理学原则 | 触发机制 | 对应模块 |
|-----------|---------|---------|
| **锚定效应** | 先展示高价，再展示目标价 | Section 6 定价 |
| **社会认同** | 展示用户数量、真实评价 | Section 4 社会证明 |
| **损失厌恶** | "免费试用，随时取消" 而非"购买" | CTA 文案 |
| **稀缺性** | "限时优惠 / 名额有限"（谨慎使用） | 定价 / 顶部 Banner |
| **权威性** | 媒体背书、数据、专家推荐 | Section 4 |
| **互惠原则** | 免费工具 / 模板 / 试用 | Hero CTA |
| **承诺一致** | 低门槛先注册，后付费 | 整体漏斗设计 |
| **FOMO** | 展示其他用户正在使用的实时动态 | 可选：通知组件 |

### 4.2 文案情绪层级

根据用户决策阶段，调整文案情绪基调：

```
Hero         → 激励型（你可以做到 / 现在开始）
痛点区        → 共情型（我们理解你的困境）
功能区        → 理性型（这是如何运作的）
社会证明      → 信任型（他们已经成功了）
定价区        → 安全型（低风险 / 有保障）
Bottom CTA   → 行动型（现在就开始）
```

### 4.3 视觉心理规则

- **F 型阅读习惯**：重要信息放左侧 / 顶部
- **视觉层级**：H1 > H2 > 正文 > 说明文字，大小比例约 3:2:1.5:1
- **白空间**：模块间距充足，避免信息密度过高引发焦虑
- **颜色**：主 CTA 按钮颜色在全页唯一，形成视觉焦点

## 五、多语言适配规范

### 5.1 AI 翻译工作流（标准流程）

```
Step 1：中文/英文原稿定稿（母语审核通过）
Step 2：AI 翻译（推荐 Claude / DeepL / GPT-4）
Step 3：提示词中附上品牌词汇表（防止品牌名/专有名词被翻译）
Step 4：母语者或双语审核（最低要求：目标市场 Native Speaker 过目）
Step 5：本地化检查（见下方清单）
Step 6：上线 A/B 测试
```

### 5.2 AI 翻译提示词模板

```
你是一位专业的本地化翻译专家，熟悉 [目标语言] 的互联网营销文案写作规范。

请将以下英文落地页文案翻译为 [目标语言]，要求：
1. 符合 [目标语言] 母语者的自然表达习惯，不要直译
2. 营销语气：[激励型/专业型/亲切型]（根据模块选择）
3. 以下品牌词汇保持原文不翻译：[产品名、功能名列表]
4. 保留所有 HTML 标签结构不变
5. 输出格式与原文结构一致

原文：
[粘贴原文]
```

### 5.3 各语言市场本地化要点

#### 🇺🇸 英语（欧美）
- 语气直接、简洁，强调个人价值（"Save YOUR time"）
- 数据单位：英制、美元
- 隐私政策：需符合 GDPR / CCPA

#### 🇯🇵 日语
- 语气礼貌、间接，强调集体/企业价值（"チームの生産性を向上"）
- 需要敬语处理，避免过于随意
- 界面文字偏长，UI 预留 30% 扩展空间
- 数据本地化承诺（日本用户对数据隐私敏感）

#### 🇰🇷 韩语
- 语气可稍活泼，강조형（强调型）文案效果好
- 缩写和新造词接受度高（科技感词汇）
- 移动端优先（韩国移动端使用率极高）
- 字符较短，UI 留白可相应调整

### 5.4 本地化验收清单

```
□ 所有品牌名/产品名保持原文（未被翻译）
□ 数字格式符合当地习惯
□ 日期格式本地化（日/月/年顺序）
□ 法律声明：隐私政策，统一用英文版本翻译
□ 错误提示文案已翻译
```

## 六、文案写作规范

### 6.1 标题公式库

| 公式 | 模板 | 示例 |
|------|------|------|
| **结果公式** | [时间] 内实现 [具体结果] | "5 分钟内生成完整会议纪要" |
| **痛点公式** | 告别 [痛点]，开始 [理想状态] | "告别手动整理，开始自动化" |
| **身份公式** | 专为 [目标用户] 设计的 [工具类型] | "专为内容团队设计的 AI 写作助手" |
| **数字公式** | [数字] [单位] 节省 / 提升 [指标] | "每周节省 10 小时重复工作" |
| **对比公式** | [旧方式] 已过时，[新方式] 更高效 | "手动翻译已过时，AI 实时翻译更高效" |

### 6.2 禁用词清单（降低信任度）

❌ 避免使用以下表达：
- "革命性的"、"颠覆性的"（过度营销，用户免疫）
- "最好的"、"最强的"（无法证明的绝对化表达）
- "简单易用"（每个产品都说，毫无区分度）
- "一键XX"（如果实际不是一键，损害信任）
- "AI 驱动"（过于泛滥，已失去差异化价值）

✅ 替换方向：
- 用**具体数据**代替形容词
- 用**用户证言**代替自我声称
- 用**流程演示**代替功能描述

### 6.3 正文长度规范

| 模块 | 建议字数（英文） |
|------|----------------|
| Hero 主标题 | 6-10 词 |
| Hero 副标题 | 20-35 词 |
| 功能亮点说明 | 15-25 词/条 |
| 用户评价 | 30-60 词/条 |
| FAQ 答案 | 50-120 词/条 |
| 整页总字数 | 800-1500 词（SEO 友好范围） |

## 七、CTA 规范

### 7.1 CTA 层级设计

每个落地页设置 **3 个层级** 的 CTA：

```
主 CTA（Primary）  — 最高优先级行动，出现在 Hero + Bottom
次 CTA（Secondary） — 如"立即试用"，出现在 Hero 旁
软 CTA（Soft）     — 如"立即开始"，出现在各 Section 底部
```

### 7.2 CTA 文案公式

```
[动词] + [对象/内容] + [可选：时间/价值修饰]

✅ 好的 CTA：
- "免费开始使用"（低门槛）
- "立即生成我的报告"（个性化 + 即时感）


❌ 差的 CTA：
- "提交"
- "点击这里"
- "了解更多"（作为主 CTA）
```

### 7.3 CTA 按钮设计规范

- 颜色：全页唯一高对比色（与品牌色区分）
- 大小：最小点击区域 44px × 44px（移动端标准）
- 位置：首屏可见范围内必须出现一次
- 周围留白：按钮四周留出足够空白，避免视觉竞争

## 八、复用清单 Checklist

每次开发新 AI 工具落地页时，按以下清单执行：

### 📋 启动阶段

```
□ 确定产品核心价值主张（一句话）
□ 确定目标用户画像（1-2 个主要 Persona）
□ 完成关键词研究（主词 + 次级词 + 长尾词）
□ 竞品落地页分析（3-5 个竞品）
□ 确定语言版本（英/日/韩）
```

### 📝 内容生产阶段

```
□ 按 8 个 Section 模板撰写英文原稿
□ 英文文案母语审核
□ 使用 AI 翻译日语/韩语版本（附品牌词汇表）
□ 日语版本敬语检查
□ 韩语版本本地化检查
□ 所有语言版本完成本地化验收清单
```

### 🛠 技术实施阶段

```
□ TDK（Title/Description/Keywords）各语言版本填写
□ hreflang 标签正确配置
□ Schema Markup 添加（SoftwareApplication + FAQ）
□ 图片 alt 属性全部填写
□ 页面加载速度测试（PageSpeed Insights）
□ 移动端显示测试
□ 表单功能测试（各语言版本）
```

### 🚀 上线后阶段

```
□ Google Search Console 提交 Sitemap
□ 设置 Analytics 目标转化追踪
□ A/B 测试计划制定（至少测试 Hero 文案）
□ 首周数据监控（CTR / 转化率 / 跳出率）
□ 关键词排名跟踪设置
```
